# Baseline verificado — 29/07/2026

Estado de los formatos, estándares y prácticas sobre los que se construye esta plantilla.
Revalidar con `/sdd-refresh`. Cadencia sugerida: trimestral, o antes si cambia una plataforma.

> **Qué es y qué no es.** Esto documenta lo que se **verificó** en la fecha de corte, con la
> fuente. Lo que no aparece aquí no se ha comprobado. No hay catálogo finito y universal de
> "todas" las arquitecturas o patrones: se cubren las familias reconocidas y se obliga a
> justificar la elección.

## 1. Formatos de agentes por IDE

| Superficie | Ubicación verificada | Campos de frontmatter | Fuente |
|---|---|---|---|
| **Claude Code** | `.claude/agents/*.md` | `name`, `description`, `tools`, `disallowedTools`, `model` (`opus`\|`sonnet`\|`haiku`\|`inherit`), `mcpServers`, `hooks` | [docs](https://code.claude.com/docs/en/sub-agents) |
| **VS Code (Copilot)** | `.github/agents/*.agent.md` **y** `.claude/agents/` | `name`, `description`, `tools`, `model`, `target`, `handoffs` | [docs](https://code.visualstudio.com/docs/agent-customization/custom-agents) |
| **Copilot** (CLI y nube) | `.github/agents/*.agent.md` | `name`, `description`, `tools`, `mcp-servers` | [docs](https://docs.github.com/en/copilot/concepts/agents/cloud-agent/about-custom-agents) |
| **Cursor** | `.cursor/rules/*.mdc` (+ `agents/`, `commands/`) | `description`, `globs`, `alwaysApply` | [ref](https://www.morphllm.com/cursor-rules-best-practices) |
| **Antigravity** | `.agents/rules/*.md`, `.agents/workflows/*.md`; global en `~/.gemini/GEMINI.md` | Markdown sin frontmatter; límite ~12 000 caracteres por fichero | [docs](https://antigravity.google/docs/rules-workflows) |

**Hallazgo con más impacto**: VS Code acepta `.claude/agents/` como ubicación de workspace.
Eso permite mantener **una sola definición canónica** en vez de duplicar 20 ficheros.
Los `.github/agents/*.agent.md` de esta plantilla son envoltorios finos que además aportan
`handoffs`, función exclusiva de VS Code.

**Nota sobre `.chatmode.md`**: formato anterior de VS Code. Renombrar a `.agent.md`.

## 2. Skills y hooks

| Elemento | Verificado |
|---|---|
| Skills | Estándar abierto **Agent Skills** (`SKILL.md`). En Claude Code, `.claude/skills/<nombre>/SKILL.md`. Frontmatter: `name`, `description`, `allowed-tools`, `disable-model-invocation`, `context`, `agent` |
| Comandos | `.claude/commands/*.md` y skills están unificados: ambos generan `/<nombre>` |
| Hooks | Registrados en `settings.json`. Eventos usados aquí: `SessionStart`, `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `SubagentStart`, `SubagentStop`, `Stop` |
| Protocolo de hooks | JSON por stdin; salida por código de salida (`0` permite, `2` bloquea) **o** por JSON con `hookSpecificOutput.permissionDecision` (`allow`\|`ask`\|`deny`) |

**Decisión**: se usa la salida JSON en las guardas porque permite `ask` —escalar al humano—
y no solo permitir o bloquear. Un `terraform apply` legítimo no debe bloquearse, pero tampoco
pasar sin preguntar.

**Antigravity** entrega el payload como `{ toolCall: { name, args } }` en vez de
`{ tool_name, tool_input }`. Los hooks de `.claude/hooks/` normalizan ambos.

## 3. Circuito SDD

Referencia: **GitHub Spec Kit** — `constitution → specify → clarify → plan → tasks → analyze
→ implement`, más `checklist` y `taskstoissues`.
Fuente: [github/spec-kit](https://github.com/github/spec-kit).

**Adaptaciones de esta plantilla**:
- Se añade `/sdd-verify` y `/sdd-ship` como fases explícitas con gates.
- Se añade `/onboard` para adoptar repos existentes, que Spec Kit no cubre.
- Se añade `/sdd-refresh` (este mecanismo) y `/sdd-status`.
- La convergencia spec ↔ código ↔ evidencia se materializa en `evidence.md`.

## 6. Skills públicas evaluadas

Popularidad sirve para **descubrir**, no para conceder confianza. Ninguna skill de terceros
se instala sin revisar licencia, versión fijada, permisos, dependencias y colisión de triggers.

| Fuente | Señal aprovechada | Decisión |
|---|---|---|
| [anthropics/skills](https://github.com/anthropics/skills) | Estructura oficial `SKILL.md` + scripts + referencias | Adoptada la estructura |
| [obra/superpowers](https://github.com/obra/superpowers) | Brainstorming previo, plan aprobado, TDD real, revisión antes de merge | Ideas incorporadas en skills propias; **no** se instala el framework completo para no tener un segundo orquestador compitiendo con el nuestro |
| [github/awesome-copilot](https://github.com/github/awesome-copilot) | Catálogo comunitario de agentes y chatmodes | Fuente de descubrimiento; cada recurso requiere auditoría individual |
| [github/spec-kit](https://github.com/github/spec-kit) | Flujo SDD y separación qué/cómo | Integrado en el circuito |

**Descartado**: incorporar colecciones masivas completas. Aumentan colisiones de triggers,
consumo de contexto, superficie de ejecución y deuda de actualización.

## 7. Sin verificar / pendiente

- Comportamiento de `handoffs` de VS Code en la versión concreta que use el usuario.
- Disponibilidad de `SubagentStart`/`SubagentStop` en hosts distintos de Claude Code:
  la trazabilidad `observed` degrada a `declared-direct` donde no existan.
- Formato de hooks de Cursor y Antigravity: se documenta la intención, no se ha probado
  en esas superficies.
- Compatibilidad con `.specify/` de Spec Kit: conceptual, no se han generado sus ficheros.
